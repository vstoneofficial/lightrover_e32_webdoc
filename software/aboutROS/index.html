    ROSとは

    ROSの概要と基本的な機能について解説します。

    ROS 1とROS 2

    ROSには「ROS 1」と、その後継として開発された「ROS 2」があります。ライトローバー E32はROS 2を使用していますので、本ドキュメントでもROS 2を前提として解説を行います。

    以下は、ROS 1とROS 2の開発時に重視された用途や、設計上の想定の違いをまとめたものです。

    ROS 1

    • 学術的な用途を目的として開発
    • 単体のロボットを想定
    • 豊富な計算資源が前提
    • 当初の設計では、リアルタイム処理を主な対象としていない
    • 有線などの十分なネットワーク帯域環境を想定


    ROS 2

    • 商用利用も視野に開発
    • 群ロボットにも対応
    • 組込みレベルも想定
    • リアルタイム処理への対応を考慮した設計。ただし、実現にはOSや実装などの対応が必要
    • 低品質なネットワークも想定

    概要

      ROS（Robot Operating System）は、Open Roboticsによって開発・メンテナンスされているロボット用のミドルウェアです。分散処理が求められる複雑なロボットシステムを制御できる性能を備えており、世界中の研究者や開発者が作成した豊富なライブラリを使用することができます。ロボット制御システムの作成を効率化できることから、人型ロボットから車両型ロボット、水上・水中ロボットやドローンに至るまで、幅広い分野で活用されています。

      ROS 2はオープンソースとして公開されており、主要なコアパッケージの多くはApache License 2.0を採用しています。ライセンス条件に従うことで、商用利用することも可能です。ただし、パッケージや依存ライブラリによってライセンスが異なるため、使用するソフトウェアごとに利用・配布の条件を確認する必要があります。

    ROSが提供する基本機能

    ROSによって提供される主要な機能について、説明します。

    メッセージ通信

      ROSを用いて構成されるロボットシステムは分散処理が基本となっており、ユーザーは「ノード」と呼ばれるプログラムを複数立ち上げることでロボットを制御するためのシステムを構成します。例えば、ゲームパッドで操作できる台車ロボットであれば、「ゲームパッドの入力値を取得するノード」、「入力値に従って移動指令を出すノード」、「移動指令をもとにモータを回転させるノード」などが必要となります。当然、ノード間で情報を通信する仕組みが求められます。各ノード間で、センサ入力値の情報やカメラの映像、制御指令値といったデータをやり取りするために、ROSではPub/Sub方式によるメッセージ通信が提供されています。開発者はわずか数行のコードにより、任意の情報をパブリッシュ（配信）したり、サブスクライブ（購読）したりすることができます。メッセージには、構造体のようにデータの型が定められています。共通の型を使うことで、ノード間でデータの形式をそろえてやり取りできます。ただし、通信するノード間では、トピック名とメッセージ型を一致させ、互換性のある通信設定を使用する必要があります。メッセージ型は自作することもできます。

    パッケージ管理

      ROSのライブラリやプログラムは、パッケージという単位で管理されています。パッケージの中にはノードやその設定ファイル、起動スクリプトなどが含まれており、ユーザは使用したい機能を持つパッケージをインターネット上からダウンロードし、ローカル環境に組み込むことができます。パッケージの追加や削除といった操作は非常に簡単に行う事ができます。また、ユーザーが独自の制御プログラムを開発する際には、まずパッケージを作成し、その中で開発を行う事になります。

    デバイスドライバ

      センサーからアクチュエーターまで、様々なデバイスのドライバーがパッケージの形式で提供されています。対応しているデバイスであれば、ドライバパッケージを導入し、デバイスの接続と必要な設定を行うことで、ROS 2から利用できます。

    ハードウェア抽象化

      ROSでは、ハードウェアごとの違いをドライバ側で扱い、共通の形式のメッセージとしてデータをやり取りできます。そのため、同じインターフェースに対応する機器であれば、ハードウェアが異なっても上位の処理を再利用しやすくなります。例えば未知環境の地図を作成するSLAM機能を提供するパッケージ「SLAM Toolbox（パッケージ名：slam_toolbox）」では、周囲の障害物の情報をレーザー光を用いた測距センサであるLRFで取得することになっています。LRFから情報を取得する部分には、機器に対応したドライバパッケージを使用します。必要なデータ形式や設定条件を満たすLRFであれば、ドライバを変更しても上位の処理を再利用しやすくなります。このように、機器ごとの違いをドライバ側で扱うことで、共通の制御システムを構築できます。

    視覚化ツール

      ROSには、いくつかの視覚化ツールが存在しており、ロボットの操縦UIやデバッグ等のために活用されています。中でも「RViz」は強力なツールです。3D表示機能を持つこのツールは、実に多くのパッケージで情報を表示するために使われています。表示情報のカスタマイズが容易ですので、ユーザオリジナルのUIを作成することも容易です。

    ロギング

      「rosbag2」はロボットを開発する上で大変有用なログ記録ツールです。rosbag2を用いることで、その時にROS上でやり取りされていたメッセージを記録することができます。これにより、ロボットを動作させた後にその挙動について細かく分析したりすることが可能です。他にも、カメラ映像やLRFセンサの信号を記録しておき、後からSLAMによる地図作成など負荷の大きな作業を実行するといったこともできます。

    ROSに関する情報の集め方

      ROSを用いた開発を行う際には、使用するパッケージの情報など、様々な情報が必要になります。ROSやその開発に関する情報は書籍から集めることもできますが、ここではインターネットから情報を集める際に参考になるサイトをいくつかご紹介します。

    ROS Developer Documentation - https://docs.ros.org/
      ROSの公式ドキュメントです。ROSのインストール方法からチュートリアルなど、様々な情報が公開されています。ただ、パッケージの情報などが更新されないまま古くなっていることもありますので、ご注意ください。

    Robotics Stack Exchange - https://robotics.stackexchange.com/
      ROSを含むロボット開発に関するQ&Aサイトです。エラーの解消方法などを調べたり、質問を投稿したりできます。従来のROS Answersは、過去の質問・回答を閲覧するためのアーカイブとして公開されています。

    ROS Japan UG - https://rosjp.connpass.com/
      日本のROSユーザーの会。勉強会などが積極的に開催されており、どなたでも参加することができます。こういったユーザーコミュニティの活発さもROSの特徴のひとつです。
