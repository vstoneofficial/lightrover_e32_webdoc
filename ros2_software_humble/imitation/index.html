    模倣学習で走らせよう

    人がマウスで運転したときの「LiDARの見え方」と「操作」を記録し、小さなニューラルネットワークに学習させて、ライトローバー E32を同じように走らせてみましょう。
    このように、人のお手本（デモ）をまねるようにAIを学習させる手法を「模倣学習」、その中でも最も基本的なものを「Behavior Cloning（行動クローニング）」と呼びます。

    このサンプルでは、次のサイクルを繰り返してAIの走り方を育てていきます。 

    デモ収集（人が運転） → 学習（PCで1～2分） → AI走行 → 人が修正 → 再学習 …

    SLAMやナビゲーションとは異なり、地図は使いません。
    AIが学習するのは決まったルートではなく「この見え方なら、こう動く」という運転のしかたです。
    そのため、コースの配置を変えても走れる ことがこのサンプルの見どころです。

    また、実機の代わりにPC上のシミュレータを使って同じ手順を試すこともできます。
    シミュレータで学習したモデルを、そのまま実機で走らせることも可能です（後述の「シミュレータで学習する」を参照）。

    Note

    このページの手順は、ソフトウェアセットアップ（ROS2 Humble）が完了していることを前提としています。
    また、マウス入力で走行でライトローバー E32がマウスで操作できることを確認しておいてください。
    ROS 2 Jazzy（Ubuntu 24.04）を使用している場合は、Jazzy版のページを参照してください。

    仕組み

    サンプルは次のノードで構成されています。 

     人の操作 (mouse_teleop) ─> /il/human_cmd ─┐
                                            ├─ il_cmd_mux ─> /il/cmd ─> twist_limiter ─> /rover_twist ─> 実機 (またはシミュレータ il_sim)
 il_policy (学習した方策) ─> /il/policy_cmd ┘   (人が優先)

 /scan ──┬─> il_recorder : 人が操作している瞬間の (スキャン, 操作) を ~/il_data に保存
         └─> il_policy   : スキャン → 特徴量(36方向の最小距離) → ニューラルネット → 速度指令
    ノード / スクリプト 役割
    il_recorder 人が操作している瞬間のLiDARスキャンと操作量をペアにして保存します
    il_cmd_mux 人の操作とAIの指令を切り替えます。人が操作するとすぐに人の操作が優先されます
    il_policy 学習済みモデルを使って、LiDARスキャンから速度指令を出します
    train.py 記録したデータからモデルを学習するスクリプトです（PyTorchを使用、ROS不要）
    il_sim 実機の代わりに動くシミュレータです。実機と同じ/scanを出力し、/rover_twistを受け取って動きます
    sim2d.py ROSを使わずに一連の流れを試せるオフライン用の簡易シミュレータです

    AIへの入力（特徴量）は「ロボットの正面を0°として360°を36方向に分け、各方向で一番近い物体までの距離」です。
    AIの出力は「前進速度」と「旋回速度」の2つです。

    準備

    パッケージの確認

    模倣学習サンプルはlightrover_e32_imitationパッケージとして、ライトローバー E32のROS 2パッケージ（mainブランチ）に含まれています。
    ソフトウェアセットアップでビルドしたワークスペースに、次のフォルダがあることを確認してください。 

    ls ~/ros2_ws/src/lightrover_e32_ros2/lightrover_e32_imitation

    フォルダが見つからない場合や、シミュレータの起動ファイル（launch/sim.launch.py）がない場合は、パッケージを最新版に更新してからビルドしなおしてください。 

    cd ~/ros2_ws/src/lightrover_e32_ros2
git pull
cd ~/ros2_ws
colcon build --symlink-install
source ~/ros2_ws/install/local_setup.bash

    操作用パッケージのインストール

    デモの記録にはmouse-teleopを使用します（キーボードで操作する場合はteleop-twist-keyboardとxterm）。
    まだインストールしていない場合は、下記のコマンドでインストールしてください。 

    sudo apt install ros-humble-mouse-teleop ros-humble-teleop-twist-keyboard xterm

    学習用環境（PyTorch）の作成

    モデルの学習（train.py）にはPyTorchが必要です。
    学習専用の仮想環境（venv）を作成し、そこにPyTorchをインストールします。
    Ubuntu 22.04ではシステムのPythonにpip install --user torchでインストールすることもできますが、依存パッケージとして新しいsetuptoolsなどが~/.localにインストールされ、ROS 2 Humbleのcolcon buildで警告やエラーが出るようになることがあります。そのため、venvの使用をおすすめします。 

    sudo apt install python3-venv
python3 -m venv ~/il_venv
~/il_venv/bin/pip install torch --index-url https://download.pytorch.org/whl/cpu
~/il_venv/bin/pip install numpy matplotlib

    --index-url ...cpuを付けるとCPU版のPyTorchがインストールされます。
    付けない場合は数GBあるCUDA版がインストールされます。このサンプルはCPUで十分に学習できます。

    Note

    ロボットを走らせるノード（il_policy）はnumpyだけで動作するため、PyTorchは学習にのみ使用します。
    学習を別のPCで行う場合も、同じ手順でvenvを作成し、記録したデータフォルダ（~/il_data）をコピーすれば学習できます。

    コースを作る

    机の上などに、箱や板を使って周回コースを作ります。

    • 通路幅は40cm以上 にしてください。ライトローバー E32のLiDARは12cmより近い物体を計測できず「何もない」と判定するため、壁に寄りすぎると壁が見えなくなります。
    • 机から落下しないよう、コースの外周は必ず壁で囲んでください。

    デモを収集する

    ターミナルを起動し、下記コマンドでROS 2とMicro-ROSを統合するためのエージェントノードを起動します。 

    cd ~/uros_ws
ros2 run micro_ros_agent micro_ros_agent udp4 --port 8888

    エージェントノードを実行した状態でライトローバー E32を起動させてしばらく待ちます。
    通信が成功すると、エージェントノードに新しい文字列が表示されます。
    その状態になったら新しいターミナルを開き、下記のコマンドでロボット本体側のノードを起動します（Rvizが起動し、LiDARのデータが表示されます）。 

    cd ~/ros2_ws
ros2 launch lightrover_e32_bringup robot.launch.py

    Warning

    mouse_teleop.launch.pyやkeyboard_teleop.launch.pyなど、操作用のlaunchファイルは起動しないでください。
    模倣学習サンプルが操作用のノードを自分で起動するため、同時に起動すると指令が競合します。

    さらに新しいターミナルを開き、下記のコマンドでデモ収集を開始します。 

    cd ~/ros2_ws
ros2 launch lightrover_e32_imitation collect.launch.py

    キーボードで操作したい場合は、teleop:=keyboardを付けて起動してください。 

    ros2 launch lightrover_e32_imitation collect.launch.py teleop:=keyboard

    向きの確認

    起動すると、ターミナルに次のような表示が2秒ごとに出力されます。 

    samples=0  前=0.45m 左=0.20m 右=0.18m

    走り始める前に、手でロボットの前・左・右に物を置き、その方向の値が小さくなることを確認してください。
    向きが正しく認識できていないと、正しく学習できません。

    運転する

    マウス操作ウィンドウでロボットを運転し、コースを 5～10周 走らせましょう。
    記録されるのは「マウスで操作している瞬間」だけなので、途中で止まって休んでも問題ありません。
    データは15秒ごとに~/il_data/demo_日時.npzへ保存されます。終了するときはCtrl+Cを押してください。

    上手に学習させるコツは次のとおりです。

    • 一定のペースで、なるべく毎回同じ走り方をする（走り方がばらばらだと、AIはその平均をとってしまいます）
    • 時計回り・反時計回りの両方を走ると、さまざまな状況に対応しやすくなります
    • わざと壁に寄ってから戻る動きを少し入れておくと、コースからずれたときに戻れるようになります

    学習する

    デモ収集が終わったら、作成したvenvのPythonで学習スクリプトを実行します。
    ロボットとの通信は不要なので、エージェントノードなどは止めてもかまいません。 

    IL=~/ros2_ws/src/lightrover_e32_ros2/lightrover_e32_imitation/lightrover_e32_imitation
~/il_venv/bin/python $IL/train.py --data ~/il_data --out ~/il_models/model.npz --mirror --plot ~/il_models/val.png

    CPUで1～2分ほどで終了し、最後に次のような評価結果が表示されます。 

    検証データでの平均誤差   直進 0.004 m/s   旋回 0.075 rad/s
(参考: 常に平均値を出すだけの場合  直進 0.004 m/s   旋回 0.310 rad/s)
曲がる場面で左右を当てた割合: 98%

    「旋回」の誤差が「常に平均値を出すだけの場合」より明らかに小さければ、学習できています。
    学習済みモデルは~/il_models/model.npzに保存されます。
    また、~/il_models/val.pngを開くと、人の操作（human）とAIの出力（policy）がどれだけ重なっているかをグラフで確認できます。

    主なオプションは次のとおりです。

    オプション 既定値 説明
    --mirror なし 左右反転したデータを追加し、データ量を2倍にします
    --max-range 1.0 これより遠い物体はすべて「遠い」として同じに扱います[m]。卓上コースなら0.5～1.0
    --sectors 36 360°を何方向に分割するか
    --hidden 64 64 ニューラルネットワークの隠れ層のサイズ
    --intervention-weight 2.0 AI走行中に人が修正したデータの重み（後述）
    --epochs 300 学習の最大繰り返し回数

    AIで走らせる

    デモ収集のときと同じように、エージェントノードとrobot.launch.pyを起動しておきます。
    その状態で新しいターミナルを開き、下記のコマンドで学習済みモデルを使った走行ノードを起動します。 

    cd ~/ros2_ws
ros2 launch lightrover_e32_imitation run_policy.launch.py

    起動直後は停止状態です。ロボットをコース上に置いたら、別のターミナルで下記のコマンドを実行して走行を開始してください。 

    ros2 param set /il_policy enabled true

    停止するときはenabledをfalseにします。 

    ros2 param set /il_policy enabled false

    走行中にマウスを操作すると、その間は人の操作が優先されます。マウスから手を離すとAIの走行に戻ります。
    速度を落としたい場合は、speed_scaleを変更してください（例：70%の速度）。 

    ros2 param set /il_policy speed_scale 0.7

    Note

    WSL2などでros2 param setがノードを見つけられない場合は、--no-daemonを付けて実行してください。
    ros2 param set --no-daemon /il_policy enabled true
    また、run_policy.launch.py enabled:=trueで起動すると、起動直後から走り始めます。

    Warning

    正面±30°に15cm未満の物体がある場合は前進しない安全装置が入っていますが、LiDARは12cm未満を計測できないため完全ではありません。
    AI走行中は必ず人が近くで見守り、すぐに止められるようにしてください。

    苦手な場面を教えて再学習する

    AI走行中に壁にぶつかりそうになったら、マウスで割り込んで正しい動きを教えましょう。
    run_policy.launch.pyの実行中も記録ノードが動いており、人が割り込んで修正した区間だけ が~/il_dataに追加で保存されます。

    その後、もう一度「学習する」の手順を実行すると、修正したデータも含めて学習しなおされ、苦手だった場面が改善されます。
    修正データは--intervention-weightで指定した重み（既定値2倍）で重視されます。

    このように「AIを走らせる → 失敗した場面だけ人が教える → 再学習する」という改善方法は「DAgger」と呼ばれ、実際のロボットAIのデータ収集でも使われている考え方です。

    シミュレータで学習する

    実機の代わりにシミュレータ（il_sim）を起動すると、「デモ収集 → 学習 → AI走行 → 修正 → 再学習」の手順をPCだけで行えます。
    il_simは実機と 同じトピック・同じ形式 で/scanを出力し、/rover_twistを受け取って動くため、collect.launch.pyとrun_policy.launch.pyは実機のときとまったく同じように使えます。 

    実機         : micro-ROS agent + robot.launch.py ─┐
                                                   ├─ /scan, /rover_twist ─ collect / run_policy (共通)
シミュレータ : sim.launch.py (il_sim)  ────────────┘

    シミュレータで集めたデータで学習したモデルを、そのまま実機で走らせることもできます。
    このように、シミュレータで学習したものを現実で使うことを「Sim-to-Real」と呼びます。

    Warning

    シミュレータと実機を同時に起動しないでください。同じトピック名を使うため、指令やスキャンが混ざってしまいます。
    同じネットワークで他の人もROS 2を使っている場合は、ROS_DOMAIN_IDを分けてください。

    シミュレータを起動する

    エージェントノードやrobot.launch.pyは起動せず、代わりに下記のコマンドでシミュレータを起動します。 

    cd ~/ros2_ws
ros2 launch lightrover_e32_imitation sim.launch.py

    Rvizが起動し、コース（茶色の壁）、LiDARの点（赤）、ロボット、走行軌跡（青線）が表示されます。緑の矢印はスタート位置です。

    course:=でコースを選べます（例：L字コース）。 

    ros2 launch lightrover_e32_imitation sim.launch.py course:=l_shape
    コース 内容
    square 四角いドーナツ形（外側1.3m四方、通路幅0.4m）。曲がり角はすべて同じ向きです（既定）
    square_wide 通路幅0.6mの四角いコース。学習していない通路幅でも走れるかの確認用です
    l_shape L字形のコース。反時計回りに走ると、左折5回と右折1回があります
    obstacles 通路幅0.6mのコースに、箱を左右交互に置いたコースです

    自分でコースを作る場合は、パッケージのcoursesフォルダにあるYAMLファイルをコピーして壁の座標を書き換え、course:=~/my_course.yamlのようにファイルのパスで指定してください。

    シミュレータの起動中は、次のコマンドでコースの切り替えやリセットができます。 

    ros2 param set /il_sim course l_shape

    ros2 service call /il_sim/reset std_srvs/srv/Empty

    コースを切り替えると、ロボットはスタート位置に戻ります。リセットすると、スタート位置に戻り、周回数などの統計もリセットされます。

    Note

    WSL2などでノードが見つからない場合は、ros2 param set --no-daemon ...、ros2 service call --no-daemon ...のように--no-daemonを付けて実行してください。

    シミュレータでデモ収集・学習・AI走行

    シミュレータを起動したまま、新しいターミナルを開いて実機と同じ手順を行います。
    実機のデータと混ざらないよう、data_dir:=で保存先を~/il_data_simに分けておきます。

    デモ収集：マウス操作ウィンドウで、Rviz上のロボットを運転してコースを5～10周させます。 

    cd ~/ros2_ws
ros2 launch lightrover_e32_imitation collect.launch.py data_dir:=~/il_data_sim

    学習：Ctrl+Cでデモ収集を終了したら、保存先と出力ファイル名を変えて学習します。 

    IL=~/ros2_ws/src/lightrover_e32_ros2/lightrover_e32_imitation/lightrover_e32_imitation
~/il_venv/bin/python $IL/train.py --data ~/il_data_sim --out ~/il_models/model_sim.npz --mirror

    AI走行：学習したモデルをmodel_path:=で指定して走らせます。enabled:=trueを付けると、起動直後から走り始めます。 

    ros2 launch lightrover_e32_imitation run_policy.launch.py data_dir:=~/il_data_sim model_path:=~/il_models/model_sim.npz enabled:=true

    実機と同じように、走行中にマウスで割り込んで修正した区間は~/il_data_simに追加されるので、再学習して改善できます。

    シミュレータを起動したターミナルには、1周するごとに次のような表示が出ます。 

    1 周 (52 秒, 衝突 0 回)

    また、10秒ごとに周回数・衝突回数・走行距離が表示されます。モデルの良し悪しを数字で比較できます。

    シミュレータで学習したモデルを実機で走らせる

    シミュレータを停止（Ctrl+C）してから、AIで走らせると同じようにエージェントノードとrobot.launch.pyを起動します。
    その状態で、シミュレータで学習したモデルを指定して走行ノードを起動します。 

    cd ~/ros2_ws
ros2 launch lightrover_e32_imitation run_policy.launch.py model_path:=~/il_models/model_sim.npz

    最初は速度を落としてから走行を開始すると安全です。 

    ros2 param set /il_policy speed_scale 0.7
ros2 param set /il_policy enabled true

    AIが学習しているのはルートではなく「LiDARの見え方に対する運転のしかた」なので、実機のコースがシミュレータのコースと同じ形である必要はありません（ただし、通路幅は近いほうがうまく走れます）。

    実機でうまく走れない場面では、マウスで割り込んで修正しましょう。修正したデータは~/il_dataに記録されます。
    --dataには複数のフォルダを指定できるので、シミュレータのデータと実機のデータを合わせて学習しなおします。 

    ~/il_venv/bin/python $IL/train.py --data ~/il_data_sim ~/il_data --out ~/il_models/model_mix.npz --mirror

    「シミュレータで大量に学習し、実機の少しのデータで仕上げる」という流れは、実際のロボットAIの開発でも使われている方法です。

    現実らしさの設定

    シミュレータでは、実機との差になりやすい要素を設定で変えられます。
    既定（realism:=real）は実機に近づけた設定、realism:=idealはノイズも遅れもない理想的な設定です。 

    ros2 launch lightrover_e32_imitation sim.launch.py realism:=ideal
    パラメータ real ideal 説明
    range_noise 0.01 0 LiDARの距離ノイズ（標準偏差）[m]
    dropout 0.02 0 LiDARの計測が抜ける割合
    range_min 0.12 0 これより近い物体は計測できない距離[m]（ライトローバー E32のLiDARは0.12）
    cmd_delay 0.10 0 指令が届いてから動き出すまでの遅れ[s]
    linear_gain 1.0 1.0 指令に対する実際の前進速度の比（電池が減ると1より小さくなるイメージ）
    angular_gain 1.0 1.0 指令に対する実際の旋回速度の比（床の滑りなど）
    motion_noise 0.05 0 動きのばらつき（指令に対する相対値）

    realの値は目安です。実機の様子を見て、パッケージのconfig/sim_real.yamlを調整してください。
    シミュレータの起動中に変更することもできます。 

    ros2 param set /il_sim cmd_delay 0.3
ros2 param set /il_sim linear_gain 0.7

    Note

    値は小数で指定してください（0ではなく0.0）。整数で指定すると型が合わずに変更できません。

    ROSなしで試す（オフライン）

    ROSやロボット実機がなくても、学習用のvenvだけで「デモ収集 → 学習 → 走行」の流れを簡易シミュレータ（sim2d.py）で体験できます。 

    IL=~/ros2_ws/src/lightrover_e32_ros2/lightrover_e32_imitation/lightrover_e32_imitation
~/il_venv/bin/python $IL/sim2d.py record --out ~/il_data_sim/demo_sim.npz
~/il_venv/bin/python $IL/train.py --data ~/il_data_sim --out ~/il_models/sim_model.npz --mirror
~/il_venv/bin/python $IL/sim2d.py eval --model ~/il_models/sim_model.npz --plot ~/il_models/sim_run.png

    四角いドーナツ形のコース（外側1.3m四方、通路幅0.4m）を「お手本役のプログラム」が走ったデータで学習し、学習したAIで周回させます。
    最後に周回数と衝突の有無が表示され、~/il_models/sim_run.pngに走行軌跡が保存されます。

    シミュレータの物理は大幅に簡略化しているため、ここで走れても実機で同じように走れるとは限りません。
    シミュレータと実機の違いを体験してみるのもよいでしょう。

    Note

    実機用のデータ（~/il_data）とシミュレータ用のデータ（~/il_data_sim）は混ぜないようにしてください。

    発展課題

    模倣学習の性質を調べる題材として、次のような実験を試してみましょう。
    記録したデータは生のLiDARデータのまま保存しているので、前処理の設定を変えるだけなら再収集の必要はありません。

    • データの量と質：周回数を2周・5周・10周と変えて、走りやすさを比較する
    • 前処理：--sectorsや--max-rangeを変えて、挙動の違いを観察する
    • データ拡張：片回りしか走っていないデータで--mirrorの有無を比べ、逆回りでも走れるか試す
    • 行動の多峰性：コース中央に障害物を置き、左右半々で避けるデモを記録すると、AIは左右の平均をとって正面衝突しやすくなります。なぜそうなるか、どうすれば解決できるかを考えてみましょう
    • DAgger：人の修正データがある場合とない場合で、周回の成功率を比較する

    シミュレータを使うと、実機では時間のかかる比較も手軽に行えます。

    • Sim-to-Real：シミュレータのデータだけで学習したモデルを実機で走らせ、どこで失敗するかを観察する。実機の修正データを少し加えるとどう変わるか比較する
    • 現実らしさの影響：realism:=idealで集めたデータのモデルを、realism:=realや実機で走らせるとどうなるか試す。cmd_delayやlinear_gainを変えた場合も観察する
    • 汎化：squareコースだけで学習したモデルを、l_shapeやobstaclesコースで走らせる。同じ手順でも、集めたデータによって走り切れる場合とL字の角で止まってしまう場合があります。どんなデータを加えれば安定するか考えてみましょう

    うまく動かないとき

    マウスを操作してもロボットが動かない

    下記のコマンドで、/il/human_cmdのPublisher（mouse_teleop）とSubscription（il_cmd_mux）のメッセージ型がそろっているか確認してください。 

    ros2 topic info /il/human_cmd
    • Humbleのmouse_teleop（1.7系）はgeometry_msgs/msg/Twistを出力します。既定の設定（mouse_stamped:=false）のままで動作します。
    • mouse_teleopを新しいバージョン（2.x）に入れ替えている場合はgeometry_msgs/msg/TwistStampedが出力されるため、mouse_stamped:=trueを付けて起動してください。 
    ros2 launch lightrover_e32_imitation collect.launch.py mouse_stamped:=true

    run_policy.launch.pyを起動する場合も同様です。
    メッセージ型が食い違っていてもROS 2はエラーを表示せず、単に指令が届かない状態になるので注意してください。

    既知の制限

    • LiDARは12cm未満の距離を計測できず、その方向は「遠い」と同じ扱いになります。通路は広めに作ってください。
    • AIの出力は「前進速度」と「旋回速度」の2つで、後退するデモには対応していません。
    • 最高速度は前進0.10m/s、旋回1.0rad/sに制限されています。launch引数max_linear_x:=・max_angular_z:=で変更できますが、変更した場合は学習時の--max-linear・--max-angularにも同じ値を指定してください。
    • シミュレータ（il_sim）の動きは「指令した速度で進む」だけの簡略版です。壁にぶつかるとその場で止まり、壁から離れる方向への移動と旋回だけができます。慣性やタイヤの滑りはmotion_noiseなどで大まかに表しているだけです。
    • シミュレータのLiDARは壁までの距離にノイズを加えただけで、黒い物体や光沢のある物体が計測しにくいといった実機のLiDARの特性は再現していません。
